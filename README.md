# Keitaro Workbench

Обёртка над Keitaro Admin API: создание кампаний с двумя потоками и редактор офферов с локальными черновиками, архивом и закреплением долей трафика.

FastAPI, Pydantic v2, SQLAlchemy 2.0 AsyncSession, PostgreSQL, Alembic. Интерфейс: Vue 3 Composition API, TypeScript и Tailwind. Зависимости зафиксированы в `uv.lock` и `frontend/package-lock.json`.

## Запуск

Нужны Python 3.12 или 3.13, [uv](https://docs.astral.sh/uv/), Node.js 24+ и Docker с Compose. Команды выполняются из корня проекта; команды `npm` ниже используют `--prefix`, переходить между папками не нужно.

```sh
uv sync --locked
npm --prefix frontend ci
npm --prefix frontend run build
```

Создайте локальную конфигурацию. Подставьте адрес своего трекера и фамилию латиницей:

```sh
uv run python -m scripts.configure --url https://tracker.example --prefix test_surname_
```

Скрипт запросит API-ключ Keitaro без отображения ввода, сгенерирует отдельный ключ приложения `APP_TOKEN`, пароль PostgreSQL и запишет `.env`. Существующий `.env` не перезаписывается. API-ключ доступен в админке Keitaro, в разделе Admin API keys. Логин и пароль админки приложению не требуются.

```sh
docker compose up -d --wait
uv run alembic upgrade head
uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**, введите значение `APP_TOKEN` из `.env`. Браузер использует только этот локальный ключ; API-ключ Keitaro остаётся на сервере. Документация обёртки: http://127.0.0.1:8000/docs.

Порт PostgreSQL по умолчанию `55439`, публикация только на `127.0.0.1`. Если он занят, измените `POSTGRES_HOST_PORT`, `DATABASE_URL` и `TEST_DATABASE_URL` согласованно до запуска. Compose предназначен для локальной разработки: обычная bridge-сеть нужна для подключения из Windows к опубликованному порту Docker Desktop. Для размещения на сервере нужны отдельная изолированная сеть БД, TLS и соответствующая конфигурация доступа.

Контейнер PostgreSQL запускается непривилегированным пользователем, с read-only корневой файловой системой, без capabilities. Данные сохраняются в именованном томе. `docker compose stop` останавливает базу с сохранением данных.

## Миграции

Миграции применяются отдельно от старта приложения:

```sh
uv run alembic upgrade head
uv run alembic current
uv run alembic check
```

Первая миграция создаёт `campaigns`, `streams` и `operations`. Последняя хранит ключи идемпотентности и состояние создания кампаний. Для отката используется `uv run alembic downgrade base`; это удалит локальные таблицы и все черновики. Кампании в Keitaro такая миграция не удаляет.

## Создание кампании

Укажите название, страну ISO 3166-1 alpha-2, оффер, домен, группу и источник. Доступные объекты загружаются из API. Префикс из `CAMPAIGN_PREFIX` добавляется автоматически.

Создаётся кампания с ротацией по позиции:

1. Обычный поток с фильтром страны и HTTP-редиректом на `GOOGLE_URL`.
2. Поток по умолчанию с выбранным оффером и долей 100%.

Повтор с тем же `Idempotency-Key` возвращает сохранённый результат. Интерфейс сохраняет ключ запроса создания до подтверждённого успеха, в том числе при перезагрузке страницы. Если соединение оборвалось после отправки запроса, проверьте кампании в Keitaro и `GET /api/v1/operations/{key}` перед новой попыткой. Неизвестный результат создания автоматически не повторяется.

Если часть потоков создать не удалось, приложение пытается отправить уже созданную кампанию в архив Keitaro. При неудаче компенсации операция остаётся в `cleanup_pending` с ID кампании; её нужно проверить вручную. Перманентное удаление не используется.

## Редактирование

- **Fetch из Keitaro** импортирует потоки. Кампании доступны только с настроенным тестовым префиксом.
- Добавление, удаление, восстановление и закрепление процентов меняют **локальный черновик** в PostgreSQL. Янтарная полоса обозначает неопубликованные изменения.
- **Push** отправляет офферы только выбранного потока и проверяет результат повторным чтением API.
- **Cancel** восстанавливает состояние до первой правки, включая состав привязок и закреплённые доли.
- Удалённая привязка остаётся в локальном архиве с нулевой долей. Сам оффер из Keitaro не удаляется.
- Повторный Fetch переносит отсутствующие в Keitaro офферы в локальный архив. Fetch при наличии черновика блокируется, чтобы не потерять работу.
- Потоки без офферов видны отдельно; их фильтры и действия редактор не изменяет. При публикации отправляется только поле `offers`, лендинги и прочие настройки сохраняются.

Проверка номера версии защищает от перезаписи из другой вкладки. Блокировка строки PostgreSQL сериализует локальные записи. Перед Push сравниваются актуальные офферы и их веса с последним Fetch. При конфликте возвращается `409`, черновик сохраняется.

Admin API не предоставляет атомарный compare-and-swap для такого изменения. Между проверкой и записью остаётся окно гонки с внешним редактором; повторное чтение обнаруживает несовпадение результата, но не гарантирует отсутствие любой внешней гонки. Это ограничение интеграции, а не обещание полной распределённой блокировки.

### Проценты

Закреплённые значения вычитаются из 100, остаток делится между незакреплёнными активными офферами. Целый остаток по одному проценту получают офферы в порядке ID. Например: закреплено 25%, два свободных оффера получают 38% и 37%.

Сумма всегда 100%, без ошибок floating point. Доли архива равны нулю. Нельзя удалить последний активный оффер, закрепить больше 100% или оставить недораспределённый остаток без свободных офферов. Нулевой вес допустим. Отключённые офферы не участвуют в распределении; при редактировании их доля нормализуется к нулю.

## Проверки

Создайте отдельную тестовую базу. Команда одинаково работает из PowerShell и Bash:

```sh
docker compose exec -T postgres sh -c 'createdb -U "$POSTGRES_USER" "${POSTGRES_DB}_test"'
uv run ruff check app tests scripts migrations
uv run ruff format --check app tests scripts migrations
uv run mypy
uv run pytest
npm --prefix frontend run lint
npm --prefix frontend run typecheck
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend audit
```

Повторно создавать уже существующую базу не нужно. Тесты применяют миграции к `TEST_DATABASE_URL` и проверяют их соответствие ORM. Защитная проверка требует имя базы с суффиксом `_test`; её таблицы очищаются между сценариями. Основная БД не используется.

Интеграционные тесты используют реальный PostgreSQL и подменённый HTTP-транспорт Keitaro. Они не создают рекламные кампании во внешнем трекере. Проверяются последовательности из видео, расчёт долей, идемпотентность, конфликты, потеря ответа после успешной записи, защита чужих кампаний и компенсация частичного создания. Интерфейс проверяется в DOM-среде Vitest/jsdom.

Для разработки интерфейса можно запустить `npm --prefix frontend run dev`: Vite проксирует `/api` на локальный FastAPI, работающий на порту 8000.

## Использование ИИ-агента

Codex использовался для разбора требований и предоставленного работодателем видео из ТЗ, изучения API, проектирования состояния черновиков, реализации и тестов. Контракт сверялся с документацией и доступным трекером. Результат проверяется командами выше; использование агента не заменяет проверку внешних изменений и понимание кода.

## Ограничения и дальнейшая работа

Это приложение для одного локального оператора. Нет пользователей, ролей, плановой очистки истории операций и автоматического восстановления незавершённых созданий. Для командной эксплуатации потребуются авторизация по пользователям, аудит действий, ограничение доступа к кампаниям и процедура сверки неоднозначных операций.

Статистику и Trends из пустых колонок видео из ТЗ приложение не выдумывает: отображаются состав офферов, их состояния и реальные доли. Отдельный QA-агент проверил приложение в настоящем Chrome на ширине 1440 и 390 px; [результаты и ограничения проверки](docs/browser-qa.md). Собственный скринкаст не записывался.
